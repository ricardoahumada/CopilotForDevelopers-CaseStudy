# Seguridad y Configuración de GitHub Copilot en VS Code y Visual Studio

La seguridad en GitHub Copilot es un aspecto fundamental que todo desarrollador debe comprender antes de utilizar la herramienta en entornos profesionales. Aunque Copilot ofrece beneficios significativos en productividad, su configuración incorrecta puede exponer información sensible de tu organización a riesgos innecesarios. Este anexo documenta las prácticas de seguridad esenciales y las configuraciones recomendadas para proteger tus proyectos mientras aprovechas todas las capacidades de la herramienta.

La arquitectura de seguridad de Copilot se basa en múltiples capas de protección que incluyen configuraciones a nivel de editor, opciones de privacidad para el procesamiento de datos, y mecanismos de control para las interacciones de agentes. Comprender estas capas te permite implementar un modelo de seguridad defence-in-depth donde cada configuración añade una barrera adicional contra posibles exposiciones de información. Las organizaciones con políticas de seguridad estrictas pueden implementar configuraciones empresariales que garanticen el cumplimiento normativo sin sacrificar la productividad del desarrollador.

## 1 Configuraciones de Seguridad en VS Code

VS Code ofrece un conjunto comprehensive de configuraciones de seguridad para GitHub Copilot que abarcan desde el control de comandos de terminal hasta la restricción de acceso a servidores MCP. Estas configuraciones se organizan en categorías lógicas que reflejan los diferentes vectores de riesgo que debes considerar. La documentación oficial de VS Code establece estas configuraciones como la referencia definitiva para la configuración de seguridad en el entorno de desarrollo.

### 1.1 Configuraciones de Agentes y Auto-Aprobación

Los agentes de Copilot en VS Code tienen la capacidad de ejecutar comandos de terminal, editar archivos, y realizar llamadas HTTP a servicios externos. Cada una de estas operaciones presenta riesgos de seguridad específicos que deben controlarse cuidadosamente. La configuración de auto-aprobación determina qué operaciones se ejecutan automáticamente sin intervención del usuario, lo cual puede ser conveniente pero también peligroso si se configura incorrectamente.

**Configuración de auto-aprobación de comandos de terminal:**

La opción `chat.tools.terminal.autoApprove` permite especificar qué comandos de terminal se auto-aprueban cuando un agente los ejecuta. Por defecto, VS Code bloquea automáticamente comandos peligrosos como eliminación de archivos o descarga de contenido desde internet. Los valores por defecto están diseñados para prevenir la mayoría de los ataques accidentales mientras permiten operaciones legítimas. Puedes personalizar esta configuración según las necesidades específicas de tu proyecto, pero debes entender completamente las implicaciones de cada decisión.

```json
{
  "chat.tools.terminal.autoApprove": {
    "rm": false,
    "rmdir": false,
    "del": false,
    "kill": false,
    "curl": false,
    "wget": false,
    "eval": false,
    "chmod": false,
    "chown": false,
    "/^Remove-Item\\b/i": false
  }
}
```

**Configuración global de auto-aprobación:**

La opción `chat.tools.global.autoApprove` controla si todos los tool calls se auto-aprueban automáticamente. Esta configuración está gestionada a nivel organizacional y requiere permisos de administrador para modificarse. Es fundamental que nunca habilites esta opción en entornos de producción ya que desactiva todas las protecciones de seguridad y permite a los agentes ejecutar cualquier operación sin confirmación.

**Configuración de ediciones de archivos:**

La opción `chat.tools.edits.autoApprove` permite especificar mediante patrones glob qué archivos requieren aprobación antes de ser editados. Esto es especialmente útil para proteger archivos de configuración críticos, archivos que contienen secretos, o cualquier archivo que no debería modificarse automáticamente. Los patrones glob permiten especificar rutas relativas al workspace con comodines para coincidir con múltiples archivos.

```json
{
  "chat.tools.edits.autoApprove": {
    "**/secrets/**": false,
    "**/.env": false,
    "**/appsettings.*.json": false,
    "**/launchSettings.json": false
  }
}
```

### 1.2 Configuraciones de Sandbox para Agentes

VS Code soporta un modo sandbox para comandos ejecutados por agentes que restringe el acceso al sistema de archivos y la red. Esta característica está disponible en macOS y Linux y proporciona una capa adicional de seguridad cuando se ejecutan agentes en código no confiable. El sandbox limita las operaciones permitidas a un conjunto predefinido que puedes personalizar según tus necesidades.

**Configuración del sistema de archivos en sandbox:**

La opción `chat.agent.sandboxFileSystem` permite configurar reglas de acceso al sistema de archivos para comandos sandboxed. Las reglas soportan propiedades `allowWrite`, `denyWrite`, y `denyRead` para controlar granularmente qué operaciones de archivos están permitidas. Por defecto, el sandbox deniega todo acceso a menos que se configure explícitamente.

```json
{
  "chat.agent.sandboxFileSystem": {
    "linux": {
      "allowWrite": ["${workspace}/**"],
      "denyWrite": ["${workspace}/**/*.key", "${workspace}/**/*.pem"],
      "denyRead": ["${workspace}/**/secrets/**"]
    },
    "mac": {
      "allowWrite": ["${workspace}/src/**"],
      "denyWrite": ["${workspace}/**/*.key"],
      "denyRead": ["${workspace}/**/.env"]
    }
  }
}
```

**Configuración de red en sandbox:**

La opción `chat.agent.sandboxNetwork.allowedDomains` especifica los dominios permitidos para acceso de red en comandos sandboxed. Por defecto, todo acceso de red está bloqueado cuando el sandbox está habilitado. Esta configuración es útil cuando necesitas permitir que agentes interactúen con APIs específicas mientras bloqueas todo otro tráfico de red.

```json
{
  "chat.agent.sandboxNetwork.allowedDomains": ["api.github.com", "registry.npmjs.org"],
  "chat.agent.sandboxNetwork.deniedDomains": ["internal.corp.local", "*.local"]
}
```

### 1.3 Seguridad de Servidores MCP

Los servidores MCP (Model Context Protocol) extienden las capacidades de Copilot permitiendo integración con herramientas y servicios externos. Sin embargo, cada servidor MCP representa un vector de ataque potencial que debe evaluarse cuidadosamente. VS Code proporciona configuraciones para controlar qué servidores MCP pueden utilizarse y qué acceso tienen al sistema.

**Configuración de acceso a servidores MCP:**

La opción `chat.mcp.access` está gestionada a nivel organizacional y determina si los usuarios pueden utilizar servidores MCP. En organizaciones con políticas de seguridad estrictas, esta opción puede estar deshabilitada completamente para prevenir el uso de servidores no autorizados. La opción `chat.mcp.discovery.enabled` controla si VS Code descubre automáticamente configuraciones de servidores MCP desde otras aplicaciones, lo cual puede introducir servidores no autorizados a tu entorno.

```json
{
  "chat.mcp.access": true,
  "chat.mcp.discovery.enabled": false,
  "chat.mcp.serverSampling": {}
}
```

**Configuración de muestreo de modelos para MCP:**

La opción `chat.mcp.serverSampling` configura qué modelos se exponen a los servidores MCP para muestreo. Esta configuración es crítica porque determina qué datos pueden ser procesados por servidores MCP externos. Por defecto, esta configuración está vacía, lo que significa que ningún modelo se comparte con servidores MCP.

### 1.4 Configuraciones de Observabilidad y Telemetría

Las configuraciones de observabilidad controlan cómo se recopilan y transmiten los datos de uso de Copilot. Aunque la telemetría puede ser valiosa para mejorar la herramienta, también puede exponer información sensible sobre tu código y patrones de desarrollo. VS Code permite granular control sobre qué datos se recopilan y dónde se envían.

**Configuración de OpenTelemetry:**

```json
{
  "github.copilot.chat.otel.enabled": false,
  "github.copilot.chat.otel.exporterType": "otlp-http",
  "github.copilot.chat.otel.otlpEndpoint": "http://localhost:4318",
  "github.copilot.chat.otel.captureContent": false
}
```

La opción `github.copilot.chat.otel.captureContent` es particularmente sensible porque determina si el contenido completo de prompts y respuestas se captura en los trazos de OpenTelemetry. Habilitar esta opción puede exponer información confidencial del código si los datos de telemetría no se protegen adecuadamente.

### 1.5 Configuración de Agentes Claude

VS Code soporta agentes Claude powered by Anthropic Claude Agent SDK. Esta funcionalidad incluye configuraciones de seguridad específicas que deben considerarse cuidadosamente antes de habilitarla.

**Configuración de seguridad para Claude Agent:**

```json
{
  "github.copilot.chat.claudeAgent.enabled": true,
  "github.copilot.chat.claudeAgent.allowDangerouslySkipPermissions": false
}
```

La opción `github.copilot.chat.claudeAgent.allowDangerouslySkipPermissions` nunca debe habilitarse excepto en entornos sandbox aislados. Esta opción desactiva todas las comprobaciones de permisos y permite al agente ejecutar cualquier operación sin restricciones.

## 2 Configuraciones de Seguridad en Visual Studio 2022

Visual Studio 2022 proporciona configuraciones de seguridad a través del menú Herramientas > Opciones > GitHub Copilot. A diferencia de VS Code, Visual Studio utiliza una interfaz gráfica para las configuraciones en lugar de archivos JSON, pero los conceptos subyacentes son similares. Las configuraciones se organizan en categorías que reflejan diferentes aspectos de la seguridad y privacidad.

### 2.1 Configuración de Exclusiones de Archivos

Visual Studio 2022 permite especificar patrones de exclusión para archivos que no deben procesarse por Copilot. Esta funcionalidad es crítica para proteger información sensible como credenciales, claves de API, y datos de clientes. Los patrones de exclusión utilizan sintaxis glob estándar y se configuran en la sección Opciones > GitHub Copilot > Archivos y patrones excluidos.

**Tipos de archivos que siempre deben excluirse:**

- Archivos de variables de entorno que contienen cadenas de conexión y contraseñas.
- Archivos de configuración específicos del entorno local con información de despliegue.
- Certificados y claves privadas utilizados para autenticación.
- Archivos de logs que pueden contener información personal.
- Archivos de configuración de infraestructura como terraform y kubernetes.

### 2.2 Configuración de Telemetría y Privacidad

Visual Studio 2022 incluye opciones de telemetría que controlan qué datos se recopilan sobre el uso de Copilot. Estas configuraciones están integradas con el sistema general de telemetría de Visual Studio y pueden gestionarse a través del menú Herramientas > Opciones > Privacidad.

**Opciones de telemetría recomendadas:**

- Deshabilitar la recopilación de datos de telemetría de Copilot si tu organización tiene políticas estrictas de privacidad.
- Revisar regularmente los datos compartidos con Microsoft para garantizar cumplimiento normativo.
- Consultar con tu departamento de compliance antes de habilitar telemetría completa.

### 2.3 Configuración de Autenticación y Cuentas

La seguridad de la cuenta de GitHub asociada con Copilot es fundamental para prevenir acceso no autorizado. Visual Studio 2022 permite gestionar múltiples cuentas de GitHub y debes asegurarte de que solo cuentas autorizadas tengan acceso a Copilot en tu entorno de desarrollo.

**Recomendaciones de seguridad de cuentas:**

- Utiliza autenticación de dos factores en tu cuenta de GitHub.
- No compartas cuentas de GitHub entre desarrolladores.
- Revoca regularmente los tokens de acceso OAuth utilizados por Visual Studio.
- Utiliza Azure Active Directory para autenticación empresarial si está disponible.

## 3 Archivo .copilotignore

El archivo `.copilotignore` en la raíz del repositorio permite definir exclusiones a nivel de proyecto que se aplican a todos los desarrolladores que utilizan Copilot en ese repositorio. Este archivo es análogo a `.gitignore` pero específicamente para Copilot. Puedes versionar este archivo junto con el código fuente para garantizar que todos los miembros del equipo utilicen las mismas exclusiones.

**Ejemplo de archivo `.copilotignore`:**

```gitignore
# .copilotignore - Patrones de exclusión para GitHub Copilot

# Archivos de configuración sensible
**/appsettings.*.json
!**/appsettings.json
**/launchSettings.json
**/appsettings.Development.json

# Archivos de entorno y secretos
**/.env
**/.env.*
**/secrets/**
**/credentials/**

# Archivos de certificados y claves
**/*.pem
**/*.key
**/*.crt
**/*.pfx
**/*.pfx

# Archivos de base de datos
**/*.db
**/*.sqlite
**/*.mdf
**/migration-scripts/**
**/Migrations/

# Archivos de configuración de infraestructura
**/terraform/**
**/kubernetes/**
**/helm/**
**/.terraform/

# Archivos de logs y temporales
**/*.log
**/logs/
**/tmp/
**/temp/

# Archivos generados
**/bin/
**/obj/
**/node_modules/
**/.vs/

# Archivos personales
**/.user
**/.suo
**/*.userosscache
```

## 4 Prácticas Recomendadas

### 4.1 Configuraciones Críticas que Nunca Deben Habilitarse

Existe un conjunto de configuraciones que nunca deben habilitarse en entornos de producción bajo ninguna circunstancia. Estas configuraciones desactivan protecciones de seguridad fundamentales y pueden resultar en compromiso de sistemas y datos sensibles. Documenta estas restricciones en tu equipo y considera implementar comprobaciones automatizadas que detecten configuraciones inseguras.

**Configuraciones prohibidas en producción:**

- `chat.tools.global.autoApprove: true` — Desactiva todas las aprobaciones de herramientas.
- `github.copilot.chat.claudeAgent.allowDangerouslySkipPermissions: true` — Desactiva todas las comprobaciones de permisos.
- `chat.mcp.discovery.enabled: true` sin controls adicionales — Puede introducir servidores MCP no autorizados.
- `github.copilot.chat.otel.captureContent: true` en producción — Puede exponer código confidencial en telemetría.

### 4.2 Modelo de Seguridad por Defecto

Adopta un modelo de seguridad donde el acceso se concede según el principio de mínimo privilegio. Por defecto, todas las operaciones危险osas deben requerir aprobación explícita del usuario. Solo después de evaluar el riesgo y establecer controles apropiados debes considerar habilitar auto-aprobación para operaciones específicas.

**Principios de seguridad recomendados:**

- Deny-by-default para operaciones de archivos y terminal.
- Allow-by-exception para operaciones específicas documentadas y aprobadas.
- Sandbox obligatorio para agentes que procesan código no confiable.
- Auditoría continua de configuraciones de seguridad.

### 4.3 Revisión Periódica de Configuraciones

Las configuraciones de seguridad deben revisarse regularmente para garantizar que siguen siendo apropiadas para el contexto actual del proyecto. Lo que era una configuración aceptable hace seis meses puede no serlo hoy si el proyecto ha evolucionado o si se han descubierto nuevas vulnerabilidades.

**Frecuencia de revisión recomendada:**

- Revisión mensual de configuraciones de agentes y auto-aprobación.
- Revisión trimestral de exclusiones de archivos y patrones.
- Revisión anual de políticas de telemetría y privacidad.
- Revisión inmediata después de cualquier incidente de seguridad.

### 4.4 Integración con Políticas Empresariales

Si tu organización tiene políticas de seguridad existentes, integra las configuraciones de Copilot con esas políticas para garantizar cumplimiento consistente. Muchas organizaciones utilizan soluciones de gestión de configuración como Intune o Group Policy para implementar configuraciones de seguridad de forma centralizada.
